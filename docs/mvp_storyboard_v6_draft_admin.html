v6 스토리보드 초안 (5/5): 관리자

관리자는 데모의 신속한 진행을 위해 계약 대리 등록부터 신차 케어 서비스 견적·확인, 출고 요청, 배송 도착, 시공 진행, 검수·수령, 정찰제 확인, 평가 제출까지 전 과정을 대신 처리할 수 있다. 포인트가 계좌정보 없이 즉시 적립되는 방식이라 "관리자가 대신할 수 없는 단계"는 없다.

신차인도서비스와 신차 케어 서비스가 서로 독립된 최상위 목록(data.reservations vs data.careOrders)으로 승격되면서, 관리자 화면도 완전히 분리된 두 개의 탭으로 나뉘었다 — 각 탭이 자기만의 목록·상세·KPI·대리처리 UI를 갖는다. 신차인도서비스 쪽은 "출고 후 시공예정" 계약에 한해 카마스터 지정업체를 경유하는 A-경로 대리처리 단계도 추가됐다.

PHASE 0

로그인 · 대시보드

1
관리자

대시보드 — 신차인도서비스 탭 (기본)

로그인하면 신차인도서비스 탭이 기본으로 열린다. 이 탭의 KPI·목록·대리처리는 신차 케어 서비스와 완전히 분리되어 있다.

PHASE 1

신차인도서비스 — 관리자 대리처리

고객요청·카마스터 승인 2단계를 건너뛰고 한 번에 계약을 등록하는 것부터, 이후 모든 버튼을 대신 누를 수 있다.

2
관리자

계약 대리 등록

담당 카마스터·고객정보·차량정보·출고 후 시공예정 여부를 한 화면에서 입력해 승인까지 건너뛴다.

3
관리자

고객 확인 대리 처리

등록된 계약을 고객 대신 확인해 계약을 확정시킨다.

4
관리자

고객 출고 요청 → 출고 요청 대리 처리

계약 확정이 곧바로 출고를 트리거하지 않는 원칙은 대리처리에서도 그대로다 — 고객 출고 요청을 먼저 대리 처리한 뒤에야 실제 출고 요청 버튼이 나타난다.

5
관리자

지정업체 경유 (A-경로) 대리처리 — 신규

"출고 후 시공예정" 계약이면, 최종 목적지 도착 전에 지정업체 구간이 하나 끼어든다. 즉시 도착 처리로 1차 구간을 끝내면, 카마스터가 업체와 소통해 확인하는 절차를 관리자가 그대로 대리한다.

6
관리자

수령 확인 → 카마스터 평가 대리 처리

버튼 문구가 "차량 확인 대리 처리 (시공 개시)"에서 "수령 확인 대리 처리"로 단순해졌다 — 시공(있었다면)은 이미 앞선 구간에서 끝난 일이라, needsService에 따라 문구가 갈릴 이유가 없어졌다.

언제든 독립적으로 · 별도 탭

신차 케어 서비스 — 관리자 대리처리

탭을 전환하면 완전히 다른 목록·KPI·상세 화면이 뜬다 — 신차인도서비스 예약과 이 목록 사이에는 UI상으로도 아무 연결고리가 없다(단, 신차인도서비스 상세에는 참고용으로 연결된 신차 케어 서비스 건이 요약되어 보인다).

7
관리자

탭 전환 → 대리 신청

이 탭 자체의 KPI(견적 대기·고객확인 대기·진행중 시공·완료)를 갖고, "+ 신차 케어 서비스 대리 신청"으로 새 건을 시작한다.

8
관리자

대상 차량 선택 → 신청

고객과 마찬가지로, 관리자도 "내 차량"(전체 신차인도서비스 예약 중 아무거나)을 먼저 고른 뒤 신청한다 — 이게 신차 케어 서비스가 독립 엔티티라는 걸 관리자 화면에서도 드러내는 지점이다.

9
관리자

견적 회신 → 견적 확인 → 입고 확인 대리 처리

"입고 확인" 단계가 새로 추가됐다 — 신차 케어 서비스는 배송 도착을 더 이상 자동 감지하지 않는다(그 차가 신차인도서비스 배송에 얹혀 왔는지 고객이 직접 몰고 왔는지 상관하지 않기 때문). 계약 완료 후에도 이 버튼을 대리로 눌러야 시공 흐름이 시작된다.

10
관리자

시공 진행 → 검수 → 2차 배송 대리 처리

작업중·작업완료 전환, 청구액(=견적가) 대리 입력, 고객 검수 요청, 오너 검수·2차 배송까지 순서대로 이어서 처리한다.

11
관리자

최종 수령 → 정찰제 확인 → 평가 대리 처리

계좌정보 입력 없이 즉시 지급되는 포인트 구조 덕분에, 평가 대리 제출까지 관리자 혼자 전 과정을 끊김 없이 완료할 수 있다.
